# WANAIA — Decision Engine & Scoring Architecture

## Deterministic, Versioned, and Explainable Mobility Scoring

---

## 1. Core Principles & Philosophy

1. **Deterministic & Reproducible:** Every score generated by WANAIA is the result of pure mathematical formulas, clear rule sets, and auditable statistical models. Running the exact same inputs against the same scoring version will always yield the exact same result.
2. **Version-Controlled & Immutable:** Scoring formulas evolve over time as data matures. Every score result permanently records its `algorithm_version`, `methodology_id`, `input_snapshot_id`, `calculated_at`, and `confidence`.
3. **No Black-Box or Arbitrary AI Scoring:** Generative AI is never permitted to assign a score. Scoring logic lives exclusively in tested Java domain services within the Spring Boot backend.
4. **Separation of Global Objective Benchmark vs. Personal Context:**
   - **WANAIA Global Score ($S_{global}$):** How good is this mobility product compared to its competitive class/market?
   - **Personal WANAIA Fit Score ($S_{fit}$):** How well does this specific product match this individual user's Mobility Profile, lifestyle, geography, and constraints?

## 3. Score Catalog & Mathematical Foundations

### 3.1 WANAIA Global Score ($S_{global}$)
*Measures the objective excellence of a vehicle variant within its market category.*

$$\text{WANAIA Score} = \sum_{k=1}^{N} w_k \cdot \phi_k(\text{Dimension}_k)$$

Where $\sum w_k = 1.0$ and $\phi_k(x)$ is the normalized category-benchmark function ($0 \dots 100$).

#### Default Global Dimensions & Weightings (Version `v1.0.0-CAR`):
| Dimension | Weight ($w_k$) | Description / Core Metrics Evaluated |
|---|---|---|
| **Reliability & Quality** | 0.20 | Historical failure rates, owner incident frequency, component longevity, warranty coverage. |
| **Safety & Driver Assistance** | 0.15 | Euro NCAP / NHTSA crash test scores, active ADAS standard equipment, chassis dynamics. |
| **Efficiency & Running Cost** | 0.15 | Real-world vs. official fuel/energy consumption ($L/100\text{km}$ or $\text{kWh}/100\text{km}$), local tax efficiency (Fiscal CV). |
| **Value & Market Positioning**| 0.15 | Equipment-to-price ratio against direct segment competitors, standard warranty terms. |
| **Practicality & Ergonomics** | 0.15 | Cargo volume ($L$), rear legroom, passenger capacity, modularity, turning circle. |
| **Performance & Dynamics** | 0.10 | Power-to-weight ratio, $0\text{-}100\text{ km/h}$, braking distance, transmission refinement. |
| **Depreciation & Resale** | 0.10 | Projected 3-year / 5-year residual value based on historical brand/model segment velocity. |

### 3.2 Personal WANAIA Fit Score ($S_{fit}$)
*Evaluates compatibility with a user's explicit Mobility Profile.*

$$S_{fit} = \frac{\sum_{i=1}^{M} \beta_i \cdot \mu_i(\text{VehicleAttr}_i, \text{UserProfile}_i)}{\sum \beta_i} \times \prod \text{HardConstraintPenalty}_j$$

#### Profile Compatibility Matrix Example:
- **Budget Fit ($\mu_{budget}$):** 
  $$\begin{cases} 
  100 & \text{if } P \le \text{Budget}_{max} \text{ and } P \ge \text{Budget}_{min} \\
  100 - 3 \times \frac{P - \text{Budget}_{max}}{\text{Budget}_{max}} \times 100 & \text{if } P > \text{Budget}_{max} \text{ (up to } 15\% \text{ stretch)} \\
  0 & \text{if } P > 1.15 \times \text{Budget}_{max} \text{ (Hard Constraint Trigger)}
  \end{cases}$$
- **Family & Passenger Fit ($\mu_{pax}$):** Penalizes vehicles with fewer seatbelts or insufficient ISOFIX anchors than required in profile.
- **Commute & Powertrain Fit ($\mu_{commute}$):** Evaluates daily mileage and city/highway ratio. If daily mileage $< 40\text{ km}$ and city ratio $> 70\%$, Hybrids and EVs receive strong positive weightings; non-adBlue diesel receives penalties.
- **Charging & Infrastructure Fit ($\mu_{ev\_charge}$):** If vehicle is BEV and user has `home_charging = FALSE` and public charger density in their postal code is low $\to$ Penalty applied with explicit explanation.

### 3.3 WANAIA Deal Score ($S_{deal}$)
*Evaluates market value for used listings against real-time market distributions.*

```
Listing Asking Price (P) vs. Market Expected Valuation (V_expected)
  V_expected = Median(Segment, Trim, Year, Market) 
               - MileageAdjustment(ActualKm - ExpectedKm) 
               + OptionsAdjustment(StandardizedFeatures)
               * ConditionFactor(InspectedState, OwnersCount)
```

#### Deal Classifications:
| Classification | Deviation from $V_{expected}$ | Deal Score Range | Badge Color |
|---|---|---|---|
| **EXCELLENT DEAL** | $P \le V_{expected} - 10\%$ | 90 – 100 | `#10B981` (Emerald) |
| **GOOD DEAL** | $V_{expected} - 10\% < P \le V_{expected} - 3\%$ | 75 – 89 | `#059669` (Green) |
| **FAIR PRICE** | $V_{expected} - 3\% < P \le V_{expected} + 4\%$ | 50 – 74 | `#F59E0B` (Amber) |
| **EXPENSIVE** | $V_{expected} + 4\% < P \le V_{expected} + 12\%$ | 25 – 49 | `#F97316` (Orange) |
| **VERY EXPENSIVE**| $P > V_{expected} + 12\%$ | 0 – 24 | `#EF4444` (Red) |

### 3.4 Total Cost of Ownership (TCO) Engine
*Calculates projected expenditure over horizons $H \in \{1, 3, 5\}\text{ years}$.*

$$\text{TCO}(H) = \text{Depreciation}(H) + \text{Fuel/Energy}(H) + \text{ScheduledMaintenance}(H) + \text{Insurance}(H) + \text{Taxes/Registration}(H) + \text{FinancingCost}(H)$$

## 4. Structured Explanation Engine (Why / Why Not)

Every score or recommendation must emit structured reasons:

```java
public record ScoreExplanationStatement(
    ExplanationType type,        // PRO (Why Recommend), CON (Why You Might Not Want It), WARNING (Constraint Alert)
    String category,             // "EFFICIENCY", "RELIABILITY", "BUDGET", "ERGONOMICS", "CHARGING"
    String code,                 // "LOW_ANNUAL_MAINTENANCE_COST", "LIMITED_REAR_LEGROOM"
    String messageTemplate,      // "Fuel consumption is {pct}% lower than segment average."
    Map<String, String> parameters,
    String dataProvenanceRef     // Reference to data point used
) {}

public enum ExplanationType {
    PRO,      // Why WANAIA recommends this
    CON,      // Why you might not want this
    WARNING   // Hard constraint mismatch (e.g. no home charging for EV)
}
```

The WANAIA AI Advisor presents these explanations in fluent conversational language but is **strictly prohibited from inventing new unsupported reasons**.

## 5. Domain Entities for Decision Traceability

```java
public record ScoreResult(
    Long id,
    String entityType,           // "MOBILITY_PRODUCT", "LISTING"
    Long entityId,
    String scoreType,            // "GLOBAL_WANAIA", "PERSONAL_FIT", "DEAL_SCORE"
    String algorithmVersion,     // "v1.0.0-CAR"
    BigDecimal scoreValue,       // 0.00 to 100.00
    String ratingClass,          // "EXCELLENT", "GOOD", "FAIR", "POOR"
    BigDecimal confidence,       // 0.00 to 1.00
    Long inputSnapshotId,
    Instant calculatedAt,
    Map<String, BigDecimal> dimensionBreakdown,
    List<ScoreExplanationStatement> explanations
) {}

public record RecommendationTrace(
    Long id,
    Long userId,
    String marketCode,
    String algorithmVersion,
    Map<String, Object> profileSnapshot,
    List<Long> candidateProductIds,
    List<Long> rankedProductIds,
    Map<Long, BigDecimal> candidateScores,
    Map<Long, List<ScoreExplanationStatement>> candidateExplanations,
    Instant generatedAt
) {}
```
